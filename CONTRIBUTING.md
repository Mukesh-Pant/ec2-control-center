## Before You Write Any Code

Read `CLAUDE.md` — it is the complete project spec, architecture guide, and code pattern
reference. Every decision made in this project is documented there. **Do not skip this.**

## Workflow

```
1. Create branch from develop
   git checkout develop && git pull origin develop
   git checkout -b feat/your-feature-name

2. Write code — follow patterns in CLAUDE.md

3. Push branch and open PR → target: develop
   git push origin feat/your-feature-name

4. Any team member approves → merge → auto-deploys to dev environment

5. Verify your feature works on the dev environment URL

6. Mukesh promotes develop → main via PR → auto-deploys to production
```

## Branch Naming

```
feat/short-description     new features
fix/short-description      bug fixes
chore/short-description    deps, config, housekeeping
docs/short-description     documentation only
```

Examples: `feat/idle-stop-config-ui`, `fix/backup-restore-error`, `chore/update-cfn-outputs`

## Commit Format

Follow conventional commits — consistent with the project's existing git history:

```
feat: add idle-stop configuration UI
fix: backup restore error for member accounts
chore: update CloudFormation outputs
docs: update CLAUDE.md with new API endpoint
refactor: extract common CORS helper
```

## Code Patterns

All established patterns are in `CLAUDE.md`. Key rules:

- **Lambda action strings:** always `.strip().lower()` before comparing — if/elif must use
  lowercase (`'setrole'` not `'setRole'`)
- **Frontend modules:** IIFE pattern — `const Module = (function() { ... return {...}; })()`
- **CORS headers** required in every Lambda response (REST API v1, not HTTP API v2)
- **Script load order** in index.html must be preserved exactly as documented in CLAUDE.md
- Never use browser `confirm()` / `alert()` — use custom in-page styled dialogs
- **API Gateway:** every resource needs an explicit OPTIONS method (NONE auth) for CORS preflight

## You Do Not Need AWS Credentials

Day-to-day development requires no AWS access. Write code, open a PR to `develop`, and the
automated pipeline deploys to the dev environment after peer approval. You can then verify
your change on the dev URL. For production debugging, contact Mukesh.

## What NOT to Commit

These are gitignored — double-check before pushing:

- `deploy-config.env` — contains AWS credentials and config secrets
- `*.zip` — build artifacts generated by deploy.sh
- `__pycache__/` — Python bytecode cache
- `.env*` files

## Updating CLAUDE.md

If your PR introduces new API endpoints, Lambda actions, frontend modules, CloudFormation
resources, or architecture decisions, update `CLAUDE.md` in the same PR. It is the
living source of truth for the entire project — keep it current.

## Referencing Issues

Link your PR to the issue it resolves so it auto-closes on merge:

```

```
